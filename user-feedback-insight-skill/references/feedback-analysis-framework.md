# 用户反馈洞察分析框架

本参考用于反馈量较多、样本存在偏差、主题之间有矛盾，或用户要求解释机会判断时。它提供判断口径与完整示例，不替代原始材料，也不把样本结论扩写成总体事实。

## 1. 证据原子

一条原始记录可能同时包含场景、问题、影响和方案。先拆为可单独判断的证据原子，每个原子保留原记录 ID；不要为了表格整齐删掉不确定性。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| 证据 ID | 可回到原始记录的稳定标识 | `FB-0004` |
| 来源 | 用户、账号、访谈或渠道标识 | `访谈-B` |
| 场景 | 问题发生的任务与上下文 | 批量导入客户数据 |
| 问题 | 阻碍用户完成任务的事实描述 | 失败后不知道错误行 |
| 影响 | 时间、失败、损失、风险或情绪 | 只能整份重传 |
| 替代方式 | 用户当前如何应对 | 手工拆分 CSV |
| 用户方案 | 用户主动提出的功能 | 下载错误行 |
| 不确定性 | 材料无法确认的内容 | 是否所有文件都会失败 |

引用代表性原话时保持简短，并在可能含个人信息时只保留完成判断所需的片段。

## 2. 重复与来源多样性

记录数回答“材料中出现了多少次”，独立来源数回答“有多少不同来源支持”。两者不可互换。

- 同一用户连续三次报告同一错误：说明持续性或复现概率上升，但独立来源仍是 1。
- 两个账号粘贴完全相同评论：可能是抓取重复，也可能是模板化反馈；在确认前同时保留两种解释。
- 同一工单在客服系统和研发系统各出现一次：属于跨系统重复，不是两份用户证据。
- 来源字段缺失：明确写“无法计算独立来源”，不要用记录条数代替。

来源多样性可按任务选择用户、账号、事件、访谈场次或渠道。必须先声明计算单位；不能在同一分析中途切换。

## 3. 主题、矛盾与异常

用用户任务或问题组织主题，例如“导入失败后的恢复成本”，而不是“错误行下载功能”。主题至少包含：

- 相关证据 ID；
- 样本内频次；
- 独立来源；
- 共性场景和影响；
- 反证、相反偏好和异常样本；
- 无法解释的缺口。

相反意见不一定互相抵消。它们可能说明用户分群、任务频率或配置需求不同。例如“默认全年”和“保持按月”的冲突，首先支持“默认值依赖使用场景”，而不是支持任意一方成为全局默认。

异常样本若严重度很高，例如数据丢失、安全问题或无法启动，即使只有一条也需保留；低频不等于低风险。

## 4. 五个独立判断维度

### 样本内频次

只描述当前材料。推荐表达：

`去重后 6 条记录中有 2 条涉及启动失败；样本来自最新差评页，不能外推总体发生率。`

### 来源多样性

- 高：多个独立用户、事件或渠道指向同一问题。
- 中：两个独立来源，或同一来源多次可复现并有日志支持。
- 低：单一来源，或来源字段缺失。

### 严重度

- 高：阻断核心任务、数据损失、安全合规风险、不可逆后果。
- 中：任务可完成，但有显著返工、等待或错误成本。
- 低：偏好、审美或非核心路径不便。

### 证据置信度

- 高：场景、版本、操作路径、结果与可复现材料完整，并有独立佐证。
- 中：问题描述具体，但缺少部分环境或覆盖面信息。
- 低：只有抽象意见、方案请求、因果推测或偏差样本。

### 战略匹配

- 高：直接服务当前目标用户、核心任务和阶段目标。
- 中：可能扩展核心价值，但需验证用户分群或时机。
- 低：面向不同市场、超出当前阶段，或需要高维护成本却缺少战略依据。

维度之间不互相替代。严重度高但证据置信度低，通常进入快速调查；频次高但战略匹配低，通常记录而不立即投入。

## 5. 产品机会

机会陈述使用以下结构：

`[目标用户] 在 [具体场景] 因 [问题] 无法或难以 [任务]，造成 [影响]。`

每个机会随后给出：

1. 相关证据 ID；
2. 反证或矛盾；
3. 样本内频次与独立来源；
4. 严重度、证据置信度、战略匹配；
5. 最大未知；
6. 最小验证动作。

不要把“做深色模式”“增加 SSO”“默认展示全年”直接写成机会。这些是用户方案或候选响应，需要先还原其任务与问题。

## 6. 行动建议

| 建议 | 使用条件 | 典型下一步 |
| --- | --- | --- |
| 立即处理 | 高严重度问题已确认，等待会扩大损失 | 止损、修复、回滚或补安全控制 |
| 进入验证 | 问题值得继续，但覆盖面或方案未知 | 复现、访谈、原型或日志验证 |
| 持续观察 | 信号存在，影响或来源不足 | 补来源字段、扩大时间窗、设监控 |
| 暂不推进 | 战略不匹配、反证明确或机会成本过高 | 记录判断条件，出现新证据再重开 |

建议必须有依据和最小动作。“继续调研”不是动作；“补 3 个不同版本的启动日志并复现升级路径”才是。

## 7. 完整示例

### 输入摘要

- `FB-0001`，用户 U-1：更新后无法打开，处于急用场景。
- `FB-0002`，与 `FB-0001` 文本重复，来源缺失。
- `FB-0003`，用户 U-2：客服建议重装后恢复。
- `FB-0004`，用户 U-3：希望增加深色模式。
- 样本来自最新差评页，不代表全部用户。

### 分析范围与限制

当前样本共 4 条，检测到 1 条可能重复；去重后 3 条。已知独立来源为 3，但重复项来源缺失，无法确认它是抓取重复还是另一用户。样本来自差评页，只能用于发现问题线索。

### 证据台账

| ID | 场景 | 问题 | 影响 | 不确定性 |
| --- | --- | --- | --- | --- |
| FB-0001 | 更新后急需打开应用 | 无法启动 | 核心任务完全中断 | 版本与设备缺失 |
| FB-0002 | 同 FB-0001 | 文本完全相同 | 同上 | 可能重复，不增加独立来源 |
| FB-0003 | 启动失败后联系支持 | 需重装恢复 | 恢复成本与数据顾虑 | 是否与 FB-0001 同一事件未知 |
| FB-0004 | 夜间使用 | 缺少深色显示 | 阅读不便 | 没有任务影响描述 |

### 主题与矛盾

`启动失败与恢复成本`：涉及 FB-0001、FB-0002、FB-0003；去重后至少 2 条记录、至少 2 个已知来源。FB-0003 提供了可恢复反证，但同时说明恢复依赖重装。没有崩溃日志和版本信息。

### 产品机会

**机会：** 已升级用户在急需使用应用时可能无法启动，并只能通过重装恢复，导致核心任务中断和潜在数据顾虑。

- 相关证据 ID：FB-0001、FB-0002、FB-0003
- 反证：FB-0003 重装后恢复
- 样本内频次：去重后 3 条记录中 2 条涉及该主题
- 独立来源：至少 2；FB-0002 来源未知
- 严重度：高
- 证据置信度：中
- 战略匹配：高
- 最大未知：问题版本、设备范围和真实发生率
- 最小验证动作：收集版本、设备和升级路径；检查启动日志并复现旧版升级

### 行动建议

`进入验证`。严重度足以立即调查，但当前材料尚不能确认影响范围或根因；先完成版本级复现和日志核对，再决定回滚、热修或定向提示。

`深色模式` 对应 FB-0004，当前为单一偏好且影响描述不足，建议 `持续观察`。

## 8. 常见错误

| 错误 | 修正 |
| --- | --- |
| 用记录百分比表示总体发生率 | 写明样本来源，只报告样本内频次 |
| 同一用户重复报告就称“多人验证” | 分开持续性和独立来源 |
| 按功能名聚类 | 按任务、问题和影响聚类 |
| 只保留多数意见 | 同时列出反证、矛盾与高严重度异常 |
| 把用户方案直接写成需求 | 先写机会，再列候选响应 |
| 用优先级掩盖不确定性 | 分别判断严重度、置信度和战略匹配 |
