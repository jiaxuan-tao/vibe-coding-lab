# Skill 前向行为评估

评估日期：2026-07-30

## 方法

三个独立代理分别收到以下指令：

```text
Use $user-feedback-insight at <skill-path> to solve the request below.
Read the Skill and any referenced file it directs you to.
Do not create or modify files.
```

代理只看到对应测试请求和本 Skill，没有收到预期答案、基线失败结论或改进目标。测试材料均为构造数据。

## 场景 A：访谈中的问题、反证和企业采购门槛

### Prompt

```text
请分析下面 6 条访谈反馈，告诉我最值得关注的产品机会以及下一步。
1. 独立开发者 A：每次导入 CSV 后字段名称不一样，我要重新对应列，很费时间。
2. 独立开发者 B：最痛苦的是不知道导入失败在哪一行，通常只能整份重来。
3. 运营 C：希望系统自动帮我修正所有错误，不想看复杂提示。
4. 独立开发者 D：字段映射我只配置过第一次，后面一直沿用，没觉得麻烦。
5. 运营 E：上传失败时，我更想先下载错误行，改完再补传。
6. 企业管理员 F：我们需要 SSO 和五级权限，否则无法采购。
```

### 真实执行关键输出（逐字摘录）

```markdown
最值得关注的机会是：

> 把“导入失败后整份重来”改造成“能定位错误行、修复后只补传失败数据”的可恢复导入流程。

这比直接做“自动修复所有错误”更可靠，也比优先优化字段映射得到更多独立证据支持。
```

```markdown
| 产品机会 | 建议 | 理由 | 依据 | 下一步 |
| --- | --- | --- | --- | --- |
| 可恢复的导入失败处理流程 | 进入验证 | 两个独立来源直接反映核心任务失败，严重度最高；但具体恢复方案仍存在偏好分歧 | FB-02、FB-05，FB-03 补充 | 先分析错误类型和失败行比例，再测试行级诊断、错误行下载、补传及安全自动修复原型 |
| 变化数据源的字段映射成本 | 进入验证 | 问题具体且贴近核心流程，但存在明确反证，可能只属于特定用户分群 | FB-01、FB-04 | 用日志验证重新映射率和数据源差异，避免直接重做全局映射体验 |
| 企业身份与权限治理 | 持续观察 | 单个来源虽构成采购阻断，但战略匹配和商业覆盖面尚未确认 | FB-06 | 核对企业销售管道；若多个高价值商机被同类要求阻断，再升级为进入验证 |
```

### 观察结果

- Pass：建立 6 条证据记录和 6 个独立来源。
- Pass：把自动修正、错误行补传和行级诊断保留为不同候选响应。
- Pass：字段映射主题同时保留 FB-01 痛点和 FB-04 反证。
- Pass：没有因采购阻断严重度高就直接承诺 SSO 和五级权限。
- Pass：行动表每个机会只使用固定建议值。

## 场景 B：重复评论和差评页抽样偏差

### Prompt

```text
这些是应用商店抓取到的 8 条评论，请总结用户痛点并给出产品机会与下一步。
1. 同步经常失败，已经第三次了。
2. 同步经常失败，已经第三次了。
3. 新版界面很好看。
4. 更新后打不开，急用。
5. 更新后打不开，急用。
6. 希望增加深色模式。
7. 客服让我重装后可以打开了。
8. 不支持导出 PDF，很遗憾。
说明：抓取脚本可能重复收录评论，且这里只是最新差评页的部分样本。
```

### 首轮发现的新缺口

首轮分析正确识别了重复、未知独立来源和差评页偏差，但行动表写出了两个新值：

```markdown
| 更新后无法启动 | **进入紧急验证** | ... |
| 新界面评价 | **保留并观察** | ... |
```

这说明“只选择一种建议”的禁止式表述不足以约束输出形状。随后先增加失败契约测试，再把 Skill 改为正向表格配方：

```markdown
| 产品机会 | 建议 | 理由 | 依据 | 下一步 |

建议列完整填写以下四个值之一：
立即处理、进入验证、持续观察、暂不推进。
```

### 修订后真实执行关键输出（逐字摘录）

```markdown
| 产品机会 | 建议 | 理由 | 依据 | 下一步 |
| --- | --- | --- | --- | --- |
| 更新后启动中断 | 进入验证 | 严重度高，应立即排查；但当前尚未确认版本范围、独立用户数和技术根因 | FB-004、005、007 | 立即启动版本级复现和日志核对；若确认当前版本存在普遍启动故障，升级为“立即处理”，评估热修、回滚或启动兜底 |
| 同步可靠性 | 进入验证 | 有重复失败和持续性线索，但可能是单一评论被重复抓取 | FB-001、002 | 建立同步成功率与错误码基线，调查连续失败事件；若发现数据损失或大范围核心任务阻断，转为“立即处理” |
| 低光环境体验 | 持续观察 | 当前仅有一个功能请求，缺少任务影响和独立来源 | FB-006 | 扩大时间窗并统计独立请求；确认明确用户群和使用场景后，再评估跟随系统的深色模式原型 |
| PDF 输出 | 持续观察 | 单一请求不足以证明核心需求，直接开发可能把格式偏好误当成任务需求 | FB-008 | 查找更多独立证据并确认输出目的；若多个核心用户存在强制 PDF 交付场景，再进入方案验证 |
```

```markdown
- 原始记录：8 条。
- 完全文本重复：FB-002 与 FB-001、FB-005 与 FB-004。
- 按文本去重后：6 条不同内容。
- 独立用户数：未知，不能把记录数当作用户数。
...
由于样本只来自最新差评页，以下结论只能用于发现问题线索，不能推断总体用户占比或真实故障率。
```

### 观察结果

- Pass：同时报告原始记录和文本去重结果，没有假定同文一定来自同一用户。
- Pass：把“第三次”解释为单条评论中的持续性线索，不当作三个独立用户。
- Pass：启动失败、同步、深色模式和 PDF 输出分别形成机会，没有按功能建议粗暴合并。
- Pass：正向界面反馈被保留为设计约束，不新增行动建议值。
- Pass：修订后行动表只使用四个固定建议值。

## 场景 C：同一用户重复、矛盾反馈与 PII

### Prompt

```text
请分析下面客服记录，尽量给出明确结论。
- 2026-07-12，王女士（手机号 13800000000）：账单页加载慢，等了十几秒；但她说最近网络也不稳定。
- 2026-07-13，用户 U-204：账单页很快，不过筛选日期后偶尔丢失筛选条件。
- 2026-07-14，李先生（li@example.com）：希望默认展示全年账单。
- 2026-07-15，用户 U-118：默认全年会太乱，希望保持按月。
- 2026-07-16，用户 U-204：再次反馈筛选返回后被重置。
- 内部客服备注：本周新版本刚上线，但没有提供版本号或设备信息。
```

### 修订后真实执行关键输出（逐字摘录）

```markdown
本次分析覆盖 2026-07-12 至 2026-07-16 的 5 条用户反馈，涉及 4 个独立用户；另有 1 条内部版本备注。材料来自客服记录，抽样方式未知，因此只能描述当前样本，不能推算总体用户占比或问题发生率。

记录含手机号、邮箱等直接身份信息，以下均已脱敏，不重复原值。
```

```markdown
E-02B 与 E-05 来自同一用户，应保留为两次记录，说明问题可能持续，但只计算为 1 个独立来源。
```

```markdown
| 产品机会 | 建议 | 理由 | 依据 | 下一步 |
|---|---|---|---|---|
| 日期筛选状态保持 | **进入验证** | 同一用户两次反馈表明问题可能持续，且影响核心账单核对流程；但独立来源只有 1 个，暂不宜直接认定为普遍故障 | E-02B、E-05 | 优先复现返回路径，补版本、设备和筛选状态日志；若确认是新版本回归，再进入修复 |
| 账单页加载性能 | **持续观察** | 慢加载有明确网络干扰因素，且存在加载很快的反证，当前无法归因产品或新版本 | E-01、E-02A、C-01 | 建立或检查页面加载耗时监控，按版本、网络类型和数据量分组；超过基线后再升级 |
| 适配不同账单时间跨度 | **暂不推进** | 两个独立来源意见相反，且都未描述严重任务阻碍；当前证据不支持把统一默认值改成全年 | E-03、E-04 | 暂时保持现状，先补使用数据和任务场景；若频繁手动切换成立，再验证记忆上次选择或个性化设置 |
```

### 观察结果

- Pass：分析中没有复述手机号和邮箱原值。
- Pass：U-204 两次记录只计算为 1 个独立来源。
- Pass：加载慢与加载快被保留为矛盾证据，未把时间相关误写成版本因果。
- Pass：全年与按月偏好被解释为潜在任务分群，不以多数投票决定默认值。
- Pass：行动表只使用固定建议值。

## 结论

三组修订后执行均满足核心输出契约。唯一在首轮发现的新失败是行动建议被自由扩写；采用逐机会表格和固定建议列后，三组独立重跑均收敛到一致结构。
