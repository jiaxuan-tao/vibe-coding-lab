# 电脑文件整理 Skill 设计说明

## 目标

构建 `computer-file-organizer` Codex Skill，帮助用户整理下载、桌面或明确指定的杂乱文件夹。

核心价值不是替用户猜测“哪些文件没用”，而是把高风险的文件移动变成一条可检查、可确认、可追踪、可撤销的操作链：

`扫描指定目录 → 生成整理计划 → 用户确认 → 执行移动 → 保存清单 → 按清单撤销`

## 已确认的产品边界

- 只处理用户明确指定的单个目录，不扫描整台电脑。
- 默认只检查目录顶层；递归扫描必须显式开启。
- 扫描和计划阶段只读，不创建分类目录，不移动、重命名或删除文件。
- 执行阶段必须由用户在看到计划后明确确认。
- 不提供删除命令；重复文件只报告，或经确认后移动到待确认目录。
- 不覆盖同名文件；目标冲突时生成安全的新文件名。
- 每次执行保存 JSON 操作清单，支持反向移动撤销。
- 撤销遇到原路径被占用时停止该项，不覆盖后来出现的文件。
- 默认忽略隐藏文件、符号链接、现有目录和无法识别的类型。
- 拒绝以文件系统根目录或用户主目录作为整理范围。
- 仅使用 Python 3 标准库，不依赖远程 API、凭证、付费服务或第三方包。
- 不将 Skill 添加到产品展示页，只更新仓库 README 与项目索引。

## 方案选择

采用“确定性计划文件 + 审批后执行”的聚焦式重实现。

未选择以下方案：

1. 纯提示词指挥 shell：实现快，但命令兼容性、同名覆盖、部分失败和撤销行为不稳定。
2. 自动监控下载目录：使用更无感，但需要常驻进程和更高系统权限，不符合轻量 Skill 的边界。
3. 直接接入完整磁盘清理工具：依赖重，删除能力过强，也会模糊“整理文件”和“清理空间”的产品目标。

## 分类与重复文件规则

首版按扩展名提供保守分类：

- 文档、表格、演示文稿；
- 图片、音频、视频；
- 压缩包、安装包、代码。

无法识别的文件保持原位。分类目录位于目标目录内部，用户可在执行前修改计划。

重复检测先按文件大小分组，只对同尺寸候选计算 SHA-256。内容哈希相同才视为精确重复；相同文件名或相似名称只作为提示，不判定为重复。重复项默认不进入移动操作，只有用户明确要求后才可在计划中加入“待确认重复文件”动作。

## 确定性脚本

提供 `scripts/organize_files.py`，包含三个子命令：

### `plan`

- 校验目标目录和安全范围；
- 扫描符合范围的普通文件；
- 统计文件类型、大小和未分类项；
- 识别精确重复组；
- 生成带源路径、目标路径、文件大小和修改时间的 JSON 计划；
- 不修改目标目录。

### `apply`

- 要求显式 `--confirm`；
- 校验计划路径均在目标目录内；
- 执行前再次核对源文件大小与修改时间；
- 创建必要分类目录并逐项移动；
- 发生同名冲突时不覆盖；
- 将成功、跳过和失败项写入历史清单；
- 部分失败时保留已成功操作的清单，便于撤销。

### `undo`

- 读取执行清单并按反序移动；
- 只撤销清单记录的成功操作；
- 原路径已存在时跳过并报告冲突；
- 不删除执行时创建的空目录。

## 输出契约

计划摘要必须依次说明：

1. 目标目录与扫描范围；
2. 文件数量、总大小与分类分布；
3. 拟移动项目及目标目录；
4. 未分类和跳过项目；
5. 精确重复组；
6. 冲突与风险；
7. 执行前需要用户确认的动作。

执行摘要必须列出成功、跳过、失败数量以及撤销清单路径。不能用“整理完成”掩盖部分失败。

## 基线测试观察

无 Skill 场景能够提出按扩展名分类、SHA-256 查重和暂存重复文件，但仍存在四个关键缺口：

- 在用户看到完整计划前就创建目录并准备移动；
- 分类与重复处理分成两段，发生中途失败时缺少统一事务记录；
- 只有 CSV 日志设想，没有可验证、可安全回放的撤销协议；
- 没有限制主目录、根目录、符号链接和计划被篡改后的越界路径。

本 Skill 通过脚本级约束解决这些问题，不能仅依赖提示词提醒。

## 测试策略

- 单元测试覆盖分类、未识别类型、隐藏文件、符号链接、递归边界和精确重复检测。
- 行为测试覆盖计划阶段只读、确认门槛、同名冲突、不覆盖、文件变化检测、部分失败和撤销冲突。
- 静态契约测试覆盖 frontmatter、触发与排除边界、输出契约、README、来源和许可证。
- 仓库集成测试确认 README 与项目索引包含 Skill，展示页不包含 Skill 卡片。
- 前向测试使用临时目录，不触碰用户真实下载或桌面目录。
