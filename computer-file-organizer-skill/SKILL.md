# 电脑文件整理

把文件整理视为需要审批的变更：**先计划，后执行；默认不删除，不覆盖，并保留撤销依据。**

## 1. 确认范围

只处理用户明确指定的一个目录。没有路径时，询问目标是下载、桌面还是其他文件夹；不要自行扫描主目录。默认只处理顶层，递归模式必须由用户明确提出。

## 2. 生成只读计划

阅读 `references/file-organization-policy.md`，然后运行：

```bash
python3 scripts/organize_files.py plan "/path/to/folder" \
  --output "/tmp/file-organization-plan.json"
```

用户明确要求处理子目录时增加 `--recursive`。默认只报告精确重复文件；只有用户已表示要把重复副本移到待确认目录时，才增加 `--include-duplicates`。

向用户展示目标范围、分类分布、计划移动、未分类项、重复组、冲突和计划文件路径。计划生成不代表执行授权。

## 3. 等待明确确认

展示计划后询问是否按该计划执行。只有用户明确确认，才能运行：

```bash
python3 scripts/organize_files.py apply \
  "/tmp/file-organization-plan.json" --confirm
```

用户说“直接整理”不能绕过计划展示；沉默、模糊同意或先前对 Skill 方向的确认，也不是对某次真实文件移动的授权。

## 4. 准确报告

报告成功、失败和 manifest 路径。`failed` 大于零时明确说明“部分完成”，列出失败原因；不要用“整理完成”掩盖部分失败。保存 manifest 作为撤销依据。

## 5. 按需撤销

只有用户明确要求撤销时运行：

```bash
python3 scripts/organize_files.py undo \
  "/path/to/manifest.json" --confirm
```

撤销遇到原路径占用时不覆盖，报告冲突并让两个文件都保持原状。

## 强制边界

- 不删除文件，不清空待确认目录，不调用 `rm`。
- 不覆盖同名目标或撤销时新出现的文件。
- 不直接整理文件系统根目录或用户主目录。
- 不跟随符号链接，不默认处理隐藏文件和已有目录。
- 不把相同名称当作重复；精确重复必须由内容哈希确认。
- 不绕过脚本自行拼接批量 `mv` 命令。
