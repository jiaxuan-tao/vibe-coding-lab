# 文件整理规则参考

## 目录

1. 默认分类
2. 扫描边界
3. 重复文件
4. 计划检查
5. 执行与撤销

## 默认分类

| 分类 | 常见扩展名 |
| --- | --- |
| 文档 | PDF、DOCX、TXT、Markdown、RTF、Pages |
| 表格 | XLSX、CSV、Numbers、ODS |
| 演示文稿 | PPTX、Keynote、ODP |
| 图片 | JPG、PNG、GIF、WebP、HEIC、SVG、TIFF |
| 音频 | MP3、WAV、M4A、AAC、FLAC、OGG |
| 视频 | MP4、MOV、MKV、AVI、WebM |
| 压缩包 | ZIP、RAR、7Z、TAR、GZ、XZ |
| 安装包 | DMG、PKG、EXE、MSI、APK、DEB、RPM |
| 代码 | Python、JavaScript、TypeScript、HTML、CSS、SQL、YAML、JSON |

没有命中默认分类的文件保持原位。不要根据文件名臆测工作、个人、项目或保密属性；这类语义分类必须由用户明确给出规则。

## 扫描边界

- 只接受用户明确指定的一个目录。
- 默认只看顶层文件；只有用户明确提出“包括子文件夹”时才使用递归模式。
- 忽略隐藏文件、符号链接、目录和已经由本 Skill 管理的分类目录。
- 不以 `/`、用户主目录或含多个不相关目录的共同父级作为目标。
- 计划文件保存在目标目录之外，确保 `plan` 阶段对目标目录零写入。
- 计划输出使用独占创建；文件已存在时换一个新路径，不覆盖旧文件。

## 重复文件

精确重复的判定顺序：

1. 先按字节大小分组；
2. 只对同尺寸候选计算 SHA-256；
3. 哈希相同才建立重复组。

相同名称、`副本`、`copy`、`final` 或版本号不能证明内容相同。默认只报告重复组，组内所有文件都保持原位；用户明确同意后，才能用 `--include-duplicates` 把每组除保留项之外的文件加入 `待确认重复文件/` 移动计划，并把保留项按普通类型归类。任何模式都不删除文件。

## 计划检查

向用户展示计划时，至少说明：

- 目标目录、是否递归；
- 可处理文件数、计划移动数和分类分布；
- 未分类文件；
- 重复组及默认保留项；
- 同名冲突产生的新名称；
- 是否包含待确认重复文件动作。

用户可以要求排除某个文件或修改目标目录。修改 JSON 后，重新展示受影响部分；不要把沉默视为确认。

## 执行与撤销

- 只有用户在当前上下文明确接受计划后才调用 `apply --confirm`。
- 执行前脚本会验证源文件大小和修改时间。文件已变化时，该项失败，不继续猜测。
- 目标路径已存在时拒绝覆盖。
- 移动使用同文件系统原子硬链接，保留 inode、扩展属性和 ACL；跨文件系统操作失败并保留源文件。
- 通过目录句柄访问源、目标和历史目录，检测分类目录或历史目录被符号链接替换的竞态。
- 执行结果中的 `failed` 大于零时，必须说明为“部分完成”。
- 保存返回的 manifest 路径；它在首次移动前创建，并逐项记录执行状态，是撤销依据。
- 异常中断留下 `moving` 状态时，撤销根据两端路径、大小和 SHA-256 判断是否恢复。
- 只有用户明确要求撤销时才调用 `undo --confirm`。
- 撤销时原路径已被其他文件占用，保留两者并报告冲突。
- 撤销时目标文件的大小或 SHA-256 与 manifest 不一致，保留当前文件并报告冲突。
- 撤销不删除执行阶段创建的空分类目录。
