一、需求背景

用户在纪念日列表中打开新增弹窗并填写名称与日期时，会遇到未填名称、未填日期、日期非法或保存失败的情况。

历史问题是上述任一情况发生后弹窗仍会关闭，已填写内容丢失；用户需要重新输入，且无法判断失败原因。

证据：用户输入描述的真实历史问题。当前没有可引用的历史数据或用户反馈明细，数据口径待确认。

二、需求目标

让用户在新增纪念日时清楚完成校验与保存：失败可修正且输入不丢失，成功后看到已更新的列表。

三、需求概述（功能清单）

本期范围
  • 纪念日新增弹窗内的名称和日期必填校验。
  • 日期非法时的页内提示与输入保留。
  • 保存未成功时保留输入、展示失败反馈并允许再次保存。
  • 保存成功后关闭弹窗并刷新当前纪念日列表。
本期不做什么 / 暂不展开
  • 不变更纪念日编辑、删除、提醒或列表筛选；这些不属于本次问题修复范围。
  • 不定义日期业务范围、时区、失败分类或统一设计规范；缺少已确认口径，留待后续确认。
  • 不接入真实服务、真实账号、生产数据或生产发布。

五、详细方案

一级模块二级功能原型描述
纪念日新增弹窗默认状态

打开可点击原型

【页面元素】

1、纪念日列表顶部含“新增”按钮；列表展示脱敏演示条目。

2、新增弹窗含标题“新增纪念日”、关闭按钮、名称输入框、日期输入框、取消和保存按钮。

3、日期输入框以 YYYY-MM-DD 为演示占位格式，最终格式待确认。

【交互说明】

1、点击“新增” → 打开空白新增弹窗。

2、点击取消或关闭按钮 → 关闭弹窗，不新增条目。

3、输入名称和日期后点击保存 → 进入保存结果判断。

【边界说明】

1、用户点击保存但两个字段均未填写 → 弹窗保持打开并分别提示。

2、用户关闭弹窗后的草稿是否保留 → 待确认，本期不定义跨关闭保留。

名称为空状态
【页面元素】

1、名称输入框显示错误描边与提示“请填写名称”。

2、日期已填写时继续展示原日期内容。

【交互说明】

1、名称为空时点击保存 → 弹窗不关闭，名称框显示提示。

2、继续输入名称 → 用户可再次点击保存。

【边界说明】

1、名称仅由空白字符组成 → 按未填写处理。

日期为空状态
【页面元素】

1、日期输入框显示错误描边与提示“请选择日期”。

2、名称已填写时继续展示原名称内容。

【交互说明】

1、日期为空时点击保存 → 弹窗不关闭，日期框显示提示。

2、补充日期 → 用户可再次点击保存。

【边界说明】

1、名称与日期同时为空 → 两个字段同时提示，两个输入均保持可编辑。

日期非法状态
【页面元素】

1、日期输入框保留用户输入的原始内容，并显示错误描边。

2、字段下方显示“请输入有效日期（YYYY-MM-DD）”。

【交互说明】

1、输入不能组成实际日期的内容后点击保存 → 弹窗不关闭并提示日期非法。

2、修改为有效日期 → 用户可再次点击保存。

【边界说明】

1、最终日期范围、闰年规则展示方式与时区口径 → 待确认。

保存失败状态
【页面元素】

1、弹窗保持打开，名称与日期继续展示用户提交前的内容。

2、保存按钮恢复可点击，按钮上方展示“保存失败，请检查网络后重试。已填写内容已保留。”

【交互说明】

1、保存未成功 → 弹窗不关闭，不刷新列表，展示失败反馈。

2、用户修改或不修改已填内容后再次点击保存 → 再次进入保存结果判断。

【边界说明】

1、连续保存未成功 → 每次保持当前输入，不叠加多条失败提示。

2、失败原因分类、重试次数和统一反馈文案 → 待确认。

保存成功状态
【页面元素】

1、新增弹窗关闭，列表中出现本次新增的脱敏演示条目。

2、页面显示“保存成功”的轻提示。

【交互说明】

1、保存成功 → 关闭弹窗并刷新当前列表。

2、刷新完成后 → 用户可在列表中看到新增条目。

【边界说明】

1、列表刷新未成功时的展示与恢复策略 → 待确认；本期核心规则仍是保存成功后才关闭弹窗。
